# Reports

Published as artifacts; the HTML here is the source of truth so the page can be
regenerated or edited without the session that made it.

| file | artifact | what it is |
|---|---|---|
| `teranoc_design_report.html` | https://claude.ai/code/artifact/fae9c1cc-9a28-4c42-a334-9afe643e0d49 | Complete design report: three-tier interconnect, group MSHR, Spatz bursts, Qwen3.8-27B kernel mapping and adopted tiles, all measured results, current limitations, glossary. |

## Regenerating / editing

The report is hand-authored HTML with six Mermaid diagrams (rendered natively by the
artifact viewer via `<pre class="mermaid">`). It is **not** generated by a script — unlike
the dashboards, which are:

| dashboard | generator | data |
|---|---|---|
| 8x8 Scale-Up Campaign | `scripts/gen_8x8_dashboard.py` | `docs/benchmarks/8x8_scaleup/results.tsv` |
| VLSU ROB Sizing | `scripts/gen_rob_dashboard.py` | `docs/benchmarks/rob_results.tsv` |
| Decode GEMM | `scripts/collect_decode_results.py` | `docs/benchmarks/decode_gemm_results.md` |

To update the report, edit this file and republish it to the same artifact URL.

## Numbers in the report and where they come from

- campaign efficiency, states — `docs/benchmarks/8x8_scaleup/results.tsv`
- dual-load / ROB sweep — `docs/benchmarks/rob_results.tsv`
- decode merge-on/off — `docs/benchmarks/decode_gemm_results.md`
- adopted tiles, kernel inventory — `docs/qwen38_kernel_mapping.md` §3–§5
- model facts, DeltaNet state wall — `docs/qwen38_workload_analysis.md`
- interconnect structure, MSHR microarchitecture — `hardware/ARCHITECTURE.md`,
  `docs/teranoc_architecture.md`, and the RTL
