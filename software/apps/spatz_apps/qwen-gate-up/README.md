# qwen-gate-up

The Qwen3.8-27B FFN gate and up projections, streamed from L2:

```
G = X . Wgate        U = X . Wup        X:[B][K]   W:[K][P]   G,U:[B][P]
```

`B` is the decode batch (independent sequences, **not** context length), `K` = hidden
= 5120, `P` = FFN intermediate = 17408. SiLU, the elementwise product and the down
projection are not here. Synthetic operands: this is a functional and performance
micro-benchmark, not a pretrained-model deployment.

---

`KERNEL_SIZE`), `mshr_cfg.h` (MSHR tuning derived from the shape), `gemm_burst.h`
(VLSU burst-eligibility model), `dma.h`, `synchronization.h`.

## 2.2 Compile-time knobs (`EXTRA_DEFINES=-D...`)

| define | default | meaning |
|---|---|---|
| `QWEN_HOLD_SUBS_BURST=n` | derived | MSHR burst subscriber target. `1` = bursts bypass, **no merging** |
| `QWEN_HOLD_SUBS_SINGLE=n` | derived | same for the scalar class |
| `ACTIVE_GROUP_DIV=n` | 1 | use only the first `NUM_GROUPS/n` groups; inactive cores get an empty range and still join every barrier |
| `KERNEL_SIZE=n` | derived | force the microkernel row count (1/2/4/8) |
| `GBAR_PLOOP=0` | 1 | drop the per-column-block group rendezvous |
| `GROUP_BARRIER=1` | 0 | enable the parent kernel's per-pair, per-step rendezvous |

Both `QWEN_HOLD_SUBS_*` are **experiment knobs**. The derived values come from the same
`gemm_config.h` split the kernel runs, which is what keeps the MSHR's targets and the
real sharing in agreement. Override only to measure, and label the result.

## 2.3 L1 capacity and P strips

L1 holds the `W` double buffer (`2 x KT x PT x 2` B), the gate and up outputs
(`2 x B x PT x 2` B), `X` and the stacks. The outputs grow with the batch, so they are
what runs out first: at K=5120, KT=160 the whole output fits up to B=64 and not beyond.

Past that the output columns are cut into **P strips** of `QWEN_PT` columns. A strip is
finished completely -- every K tile of gate, then of up -- written back to L2, and the
next strip reuses the same L1 buffers:

```
for strip in 0 .. NSTRIPS-1:
    gate: stream W[strip] K tile by K tile, accumulate G[:, strip]
    up:   stream W[strip] K tile by K tile, accumulate U[:, strip]
    fence; barrier; DMA G and U strips -> L2; prime gate of strip+1
```

- **No cross-core reduction.** Each core still owns a block of the output and runs the
  whole K loop on it; the strip only narrows the block.
- **Every DMA stays contiguous.** `W` is stored **strip-major** in L2, `[stage][strip][K][PT]`
  (`script/gen_operands.c` writes it that way), so a K tile of one strip is one run of
  `KT x PT` elements. The output goes out strip-major too, `[stage][strip][B][PT]`, one
  `B x PT` copy per stage. The DMA frontend's one-job/one-done-flag model is unchanged.
- `W` is still read from L2 exactly once (every element belongs to one strip), and `X`
  stays resident; the cost is one write-back and one barrier per strip.
- With one strip both layouts are the old row-major ones and the code path is the old
  one (no write-back, no `qwen_out_l2`).

`qwen_pt=auto` tries `LDP/1, LDP/2, ... LDP/64` and takes the first width that is a
whole number of pad units, divides `LDP`, keeps each core's span at least one full
vector load, and fits L1 (`QWEN_PT_OK`, `qwen_layout.h`). The build fails with a
`_Static_assert` if nothing fits. At K=5120 P=16384 on 8x8:

| B | KT | PT | strips | L1 used |
|---:|---:|---:|---:|---:|
| 16 / 32 / 64 | 160 | 16384 | 1 | fits |
| 128 | 160 | 8192 | 2 | 10.4 MiB |
| 256 | 160 | 8192 | 2 | 15.6 MiB |
| 512 | 160 | 4096 | 4 | fits (decode split) |

`auto` picks the prefill split for B >= 128 whenever it is legal; `qwen_split=decode`
forces the row-chunk x column-block split instead.

## 2.4 Decode group patch and row pad

Two layout choices, both measured against the split group MSHR (4-tile slices:
W bursts merge in a tile ROW, X scalars in a tile COLUMN):

- **Group patch (`qwen_rc_group`).** The original decode split puts the row chunk
  fastest in the core id, so at B=64 (8 row chunks) a group holds 8 row chunks x 2
  column blocks: W's 8 sharers straddle two row slices and X has only 2 sharers per
  column slice, below the merge threshold, so every X load bypasses the MSHR. With
  `qwen_rc_group=4` each group takes a 4 x 4 patch instead: W sharers are one tile
  row, X sharers one tile column, both merge 4-way. Shapes with <= 4 row chunks
  (B<=32 at KS=8) are unchanged. `gemm_config.h` `GEMM_DECODE_RC_PER_GROUP` is the
  one knob the split, `mshr_cfg.h`'s merge targets and `gen_hash.c` all read.
- **Row pad (`qwen_wpad`).** W and C rows are PT elements and PT x 2 bytes is a
  whole number of mesh sweeps, so every K row sits on the same group and tile: at
  any moment all W traffic comes from 2 tiles per column block (8 of 16 tiles per
  group at B=16, 4 at B=32, 2 at B=64), and those few tiles source every response.
  One 64-byte pad moves each K row one tile on, and each 16 rows one group on, so
  a K tile cycles through all tiles and the group that reads its own W (unmerged:
  local bursts bypass the MSHR) rotates instead of always being g0 and g15. The pad
  is stored in L2, so a K tile is still one DMA; buffer slots are rounded up to a
  mesh sweep so each stays aligned. In L2 each K tile also gets its own
  sweep-rounded slot (`[stage][strip][K tile][QWEN_WSLOT]`): L2 is interleaved on
  the L1 group bits, so an aligned tile keeps group g's DMA backend on L2 bank g.
  Packed back to back, padded tiles shifted that by 10 banks per tile and the
  refill time swung 15.8k-34.8k cycles around an unchanged mean, which the
  DMA-bound B=16 paid at its maximum (barrier sleep 2.5 -> 7.8 pp).

## 2.5 K tile height and the continuous W stream

A core keeps its 8 x 64 accumulator block in registers for the whole K loop of one
64-column chunk and pays ~1.5-2k cycles at every chunk boundary (C store, group
rendezvous, C reload, W restart): ~10 pp of FPU time at `KT=160`. Boundaries per MAC
fall as 1/KT, and the W double buffer `2 x KT x PT` is a fixed L1 budget, so the
default trades strip width for height: `KT=640 PT=4096` moves the same 5.25 MB per DMA
as `KT=160 PT=16384`. Every W load keeps its full vector length (at KS=8 two 16-word
bursts); the limit is one full 64-column chunk per core per strip,
`PT >= 64 x column blocks`.

`script/gen_tiles.c` chooses both on the host and writes `data/qwen_tiles.h`: the
tallest `KT = K/s` (s = 2, 4, ..., 128, an even tile count) up to `qwen_kt_max` that
leaves a legal strip, then the widest strip beside it. Full shape (K=5120 P=16384):

| mesh | B | KT x PT | strips | measured (first ~200k cycles) |
|---|---:|---|---:|---|
| 4x4 | 16 | 320 x 8192 | 2 | 95.1 % (was 88.5 at 160 x 16384) |
| 4x4 | 32, 64 | 640 x 4096 | 4 | 95.7 / 95.5 % (was 88.3 / 88.4) |
| 8x8 | 64, 128 | 640 x 16384 | 1 | 94.0 % at B=64 (was 82.8) |

More strips would add pipeline restarts, so the W stream is continuous (`main.c`,
`QWEN_STREAM`): the last two K steps of a projection prefetch the next projection's
tiles 0 and 1, and a strip's write-back runs in the barrier of its last step. The only
per-strip cost left is the output copy. It needs an even tile count (slot = step & 1);
an odd one keeps the prime-per-projection path.

# 3. Running under GVSoC

```sh
cd $TERANOC_GVSOC/gvsoc
export PATH="/home/zexifu/.local/pyshim:$PATH"
source sourceme.sh
export TERANOC_MSHR_MERGE_REQS=16        # elaboration-only in the RTL; no CSR carries it

install/bin/gvrun --target=teranoc_spatz:system_config=terapool_spatz4_fpu \
  --work-dir <rundir.d> --parameter binary=<elf> run > <rundir>.log 2>&1
```

**`--parameter binary=`, not `--target-opt=binary=`.** With `--target-opt` this fork's
runner does not load the ELF: the platform boots with nothing to execute, prints
nothing, and the MSHR's periodic event keeps the clock free-running, so the run never
ends. It looks exactly like a hang; the tell is a simulated cycle count in the billions.

Simulator profiles (`system_config=`): `terapool_spatz4_fpu`, `..._8x8`, `..._nomshr`,
`..._naive`, and `terapool_spatz4_fpu_l2_512m` / `..._8x8_l2_512m` for the 512 MiB L2
the full-size shape needs. L2 size is structural (it is in the address map and so in the
compiled platform tree), which is why it is a profile and not an env override.

## 3.1 Diagnostic logs

| env var | file | what it gives |
|---|---|---|
| `TERANOC_MSHR_CSR_LOG` | `csr.log` | every MSHR CSR write + resulting status. **Empty = the ELF never programmed the MSHR** |
| `TERANOC_MSHR_HB_PATH` | `hb.log` | heartbeat per 65536 cycles, change-gated; carries per-entry `subs=` dumps |
| `TERANOC_VLSU_STATS_PATH` | `vlsu_stats.log` | VLSU counters. **Periodic per-core dump — grows to GBs** |
| — | `mshr_stats.log` | written at teardown into the CWD; the trustworthy totals |

**Never set `TERANOC_MSHR_WIN_PATH` on an unbounded run.** One line per group per 8192
cycles, ungated; on a free-running clock it produced ~19 GB per arm in five minutes.

`vlsu_stats.log` and `hb.log` are periodic snapshots: **summing them across dumps scales
with runtime, not with work**. Use per-dump means. `mshr_stats.log` totals are teardown
values and are safe to use directly.

Compact finished runs with `qwen_refactor_run/compact.sh <rundir>.d` — it reduces
`vlsu_stats.log` to a one-line `vlsu_summary.txt`, drops the regenerable
`gvsoc_config.json`, and takes a run directory from ~2 GB to ~260 KB.

## 3.2 Reading a run

These must NOT appear, or the measurement is invalid:

```
[MSHR] SPLIT MISMATCH ... MSHR IS MISTUNED     <- targets disagree with the real sharing
[MSHR] cfg REJECTED status=0x...               <- a CSR write was refused
```

Counters that matter, in `mshr_stats.log`:

- `entry_lifetime: hold= flight= drain=` — **hold** is time waiting for the sharing
  cohort before the fetch issues. Large next to `flight` means the cohort is late, not
  that merging failed.
- `cache: selfinval= aged_out= mean_served= target=` — `aged_out` means entries never
  reached their target and sat out `serve_timeout`.
- `bank_full=` — entries occupy ways and new requests are rejected and retried.
- `single=a/b(x%) burst=c/d(y%)` — merge rates. With sharing degree `s` the theoretical
  maximum is `(s-1)/s` of requests merging; compare against that, not against 100%.

# 5. Correctness

`qwen_check` fills the L2 operands on the target with a pattern whose exact result is
known and verifies **every** output element with **integer compares of raw halfwords** —
no floating point on the checking path (scalar FP in a long core-0 loop wedges the FP-LSU).

| `qwen_check` | pattern | expected | checks |
|---|---|---|---|
| 1 | `X` one-hot at column `(3+b) mod K`, `W` a small exact grid | `C[b][p] == W[(3+b) mod K][p]` | addressing, tiling, DMA, burst path. Any `K`, needs `B <= K` |
| 2 | `X = W = 1` | `C[b][p] == K` | MAC count and accumulation across K tiles. Needs `K` a power of two <= 2048 |

Gate and up get different weights, so a swapped stage base fails. At `qwen_check=0`
nothing is written to the L2 operands: they are `.l2_bss`, reserved but absent from the
ELF, so a full-size ELF is ~130 KiB rather than 340 MiB. GVSoC timing is
data-independent, so a perf arm loses nothing by running on unwritten weights.

With several strips the check copies each strip's two output blocks back from L2 into
the L1 accumulators and all cores verify that strip in parallel; a mismatch is reported
with its stage, row and **global** column, so a wrong strip offset reads as a column
that is off by a multiple of `QWEN_PT`.

`main.c` disables the MSHR right after `mempool_stop_benchmark()` in check builds: the
verify loop is one core walking the whole output with scalar halfword loads, forming
2-subscriber cohorts against a much larger target and timing all of them out. Without
it, a check build's counters are dominated by ~16k timeouts of pure artefact, all in the
group that hosts the L1 buffers.

# 6. Code structure

## 6.1 `main.c`

| section | what it does |
|---|---|
| Derived shape | `QWEN_LDP` (padded row stride), `QWEN_STEPS`, L1 budget `_Static_assert`s |
| Storage | `qwen_w_l2` / `qwen_x_l2` in `.l2_bss`; `qwen_w[2][..]` double buffer, `qwen_c[2][..]`, `qwen_x` in `.l1_prio` |
| Synthetic operands | `qwen_*_bits()`, `qwen_fill_operands()`, `qwen_verify()` — only under `QWEN_CHECK` |
| Pipeline | `qwen_refill()` one DMA of strip `s`, tile `t`; `qwen_prime()` tile 0 + launch tile 1; `qwen_project()` the K-tile loop over one strip |
| Strips | `qwen_writeback()` fence + barrier + DMA both output strips to `qwen_out_l2`; only built when `QWEN_NSTRIPS > 1` |
| `main` steps 1–6 | work split → operands → group barrier struct → I$ warm-up + MSHR config → measured region → check |

Pipeline shape: on entry tile 0 is resident and tile 1 in flight; each iteration
computes the resident slot, barriers, waits for the in-flight tile, and launches tile
*step+2* into the slot just freed. One transfer outstanding at a time — the single
global DMA frontend has one `{src,dst,len}` register set, so a second launch would
overwrite the first descriptor.

`qwen_prime()` for the **first** projection runs *outside* the timed region: filling an
empty L1 has nothing to overlap with, so it is cold-start cost. The up projection's
prime is inside, because by then L1 is warm and a real FFN would pay it.

## 6.2 `kernel/qwen-fmatmul.c`

A fork of the tuned burst-merge kernel with **three** documented changes. Everything
else — the unroll-by-2 B ping-pong, register allocation, LMUL per `KERNEL_SIZE`, the
1xVL ROB-capacity splits, and the per-column-block `GBAR_PLOOP` rendezvous — is exactly
as in the parent.

1. **`lda`** — A's row stride, previously hardwired to `N`. A K tile hands the kernel a
   column slice of a wider `[B][K]`, so reduction length and row stride now differ.
2. **`accum`** — load the accumulators from C instead of zeroing, so tile *t* adds into
   what *t-1* left. The load mirrors the epilogue's store exactly (same registers, same
   walk); the `vfmul`-initialising peel is gone and every iteration is `vfmacc`.
3. **`qwen_burst_vl()`** — cap each vector at the next 64-byte stripe boundary,
   **unconditionally**.

### Why the cap is unconditional

A vector load bursts only if it stays inside one 64-byte tile stripe (any 4-byte-aligned
start) or starts 16-byte aligned. Full-width B=1 gives 68 columns per core starting at
byte `136*k` — 8-byte aligned, never 16 — so the parent's `p_end - p` emits a 136-byte
load that bursts not at all, on 128 of 256 cores.

Capping **only when misaligned** fixes that but makes the number of column blocks depend
on the start offset: 68 columns is one vector from an aligned start and two otherwise.
Two cores per group of 16 then run ahead, `GBAR_PLOOP`'s arrival count stops being
uniform, and the barrier stops releasing. Capping *always* costs one extra vector on the
aligned cores and keeps every core's sequence identical. Measured: 100% of vector loads
on the burst path at every batch, and the 256³ GEMM anchor bit-identical.

`script/test_burst_vl.py` replays the p-loop against a port of the runtime's own
`gemm_burst_eligible()` and asserts zero non-burst vectors for the production shapes.
**Run it after any change to the p-loop or to `QWEN_LDP`.**

# 7. Known limits and open questions

- Strip write-back is serial with compute: the next strip's gate prime waits for the
  write-back DMA. Overlapping it needs a second `C` buffer or a DMA frontend that queues.
- `X` is a single L1 copy. At B=1 every core takes its scalar operand from the few
  groups that copy occupies; the MSHR's single class absorbs it (16 cores merge into one
  remote request). A group-local `X` needs a strided per-group placement.
- **Burst merging is correct but expensive — this is the main open question.** It
  achieves 98.4% of the theoretical maximum, yet at B=2 enabling it costs 129×
  (11.3M vs 87.5k cycles): each entry holds waiting for its partner while the core has
  ~1 load in flight, so the wait is pure stall. Bypassing instead costs 1.8–2.8× more
  NoC traffic, which is the wrong trade once the operator becomes bandwidth-bound.
  Whether the answer is a tighter rendezvous for the sharers, a shorter window, or more
  VLSU occupancy is unresolved.
- At B=1 the operator is bandwidth-bound by construction: each weight element feeds one
  MAC, so 2 bytes per MAC, and 100% FPU would need 4096 B/cycle. The ceiling is ~24% even
  at the documented DMA rate. FPU utilisation is the wrong success metric at small batch;
  achieved weight bandwidth is the right one.
- Synchronisation is `mempool_barrier` twice per K tile plus the per-column-block group
  rendezvous; not yet optimised.
